# 智能路由 ContextConsensus 阶段 B-2c1 实施报告

更新时间：2026-07-24

## 1. 实施结果

本轮完成阶段 B-2c1：建立可用于最终放行的权威 token 计数与上下文上限证据契约，增加显式压缩渠道白名单和按模型、渠道、协议绑定的上下文上限配置，并实现安全的压缩子请求提示构造器。

本阶段仍未把自动压缩接入 `controller.Relay` 主链路。两个总开关继续默认关闭，压缩模型池、压缩渠道白名单和权威上下文上限默认均为空，现有请求行为不变。

## 2. 权威预算证据

`service/contextconsensus` 的 `TokenCounter` 现在返回结构化 `TokenCountResult`，最终预算判定会校验：

- 结果明确标记为权威。
- 模型、渠道 ID 和最终协议与当前候选完全一致。
- 正文摘要与被计数的最终请求正文一致。
- 计数来源和版本非空。
- 各 token 分项非负且求和不溢出。

新增 `ContextLimitResolver` 和 `ContextLimitResult`，上下文上限证据同样必须是权威结果，并严格匹配模型、渠道 ID 和最终协议。缺失、非权威、跨候选复用或元数据不一致时均失败关闭。

`EvaluateResolvedTokenBudget` 组合两类证据后计算最终预算，继续保留显式 `max_output_tokens: 0` 与字段缺失的差异，并覆盖上限前一位、恰好上限和上限后一位边界。

现有 `service.EstimateRequestToken` 和智能路由的模型名上下文推断没有被标记为权威，也没有接入最终放行路径。

## 3. 严格配置边界

`smart_routing` 配置新增：

- `compaction_channel_ids`：压缩子请求允许使用的显式渠道 ID 白名单，仅接受不重复的正整数。
- `authoritative_context_limits`：按模型配置 `max_context_tokens`、`version`、`channel_ids` 和 `relay_formats`。

上下文上限配置必须同时包含正数上限、非空版本、至少一个渠道 ID，以及至少一个受支持的最终协议。设置更新入口会在写入前校验；配置快照会深拷贝 map 和 slice，避免热更新或调用方修改污染请求内冻结值。

空白名单和空上下文上限配置是合法的禁用状态，不会自动把普通可用渠道或模型名推断结果提升为权威来源。

## 4. 安全压缩提示

新增 `BuildCompactionPrompt`，它会重新校验压缩计划与原始正文的一致性，并只提取计划覆盖的早期完整纯文本 turn。子请求固定为非流式显式真实模型请求：

- system 消息只包含固定的 ContextConsensus v1 JSON 合同和不可信数据隔离规则。
- user 消息只包含覆盖范围、来源摘要和被覆盖的 user/assistant 纯文本历史。
- 原 system/developer 指令、最近保留轮、当前用户轮、输出 schema、工具、媒体和 provider-bound 状态不会进入压缩模型载荷。
- 模型、计划或正文不匹配时拒绝构造，输出保持确定性。

## 5. 未接入主链路的原因

当前主请求在最终模型映射、协议转换、禁用字段过滤和参数覆盖之前已经完成定价与预扣；现有 `PreparedRelayRequest` 则在具体 relay handler 内、即将发送时才生成。此顺序无法保证“逐候选最终正文权威计数失败时主请求零预扣、零发送”。

同时，现有智能路由只保存所选模型的同模型重试渠道，尚未冻结可用于长上下文终检的完整跨模型候选集合。直接接入会破坏完整上下文优先、逐候选隔离和主请求原子提交要求，因此本轮保持 fail closed，不进行半接入。

## 6. 后续阶段

B-2c2 需要完成：

1. 抽取无网络的 `PrepareTextRelayAttempt`，在发送与主预扣前生成实际最终上游请求快照。
2. 冻结完整合规候选集合，并为每个候选独立解析权威 tokenizer 与上下文上限证据。
3. 增加同时持有 DTO、BodyStorage、候选、最终快照和预算证据的原子提交对象。
4. 接入最多一次压缩的 controller 编排，压缩后仍超限或任一证据失败时，在主预扣前失败关闭。
5. 覆盖默认零差异、三重授权、父子独立计费、逐候选终检和流式首字节屏障。

只有 B-2c2 的预准备、原子提交和主计费顺序门禁全部完成后，才允许评估开启生产自动压缩。

## 7. 验证范围

本轮测试覆盖：

- 权威计数的模型、渠道、协议、正文摘要、来源和版本校验。
- 权威上下文上限解析及跨候选证据拒绝。
- 输出上限显式零值、安全边际和预算临界值。
- 四协议纯文本压缩载荷只包含计划覆盖历史。
- system/developer、保留轮、当前轮和 schema 不进入子请求载荷。
- 配置格式、重复渠道、非法协议和不可变快照。

定向竞态测试 `go test -race ./service/contextconsensus ./setting/model_setting ./controller` 与全仓测试 `go test ./...` 已通过。
